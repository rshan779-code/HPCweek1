# 📘 CS6290 Project 0 — 专题 2：分支预测（Branch Prediction）⭐ 核心重点

> Project 0 的灵魂：理解各种分支预测器的工作原理、精度和硬件代价。

---

## 1. 为什么需要分支预测？

现代处理器流水线深度达 15-20 级，错误预测代价极高：

```
代价 = 流水线深度 × 时钟周期时间
例：流水线 15 级 → 错误预测浪费 15 个周期！
```

程序中大约 **15-25% 的指令是分支指令**。

```
若错误率 10%，每条指令平均代价：
  15% × 10% × 15 cycles = 0.225 cycles/instruction
→ CPI 从 1.0 变成 1.225，性能下降 22.5%！
```

## 2. 分支预测器全景图

```
分支预测器
├── 静态预测（Static）
│   ├── 总不跳（Always Not Taken）
│   ├── 总跳（Always Taken）
│   └── BTFN（Backward Taken, Forward Not Taken）
└── 动态预测（Dynamic）
    ├── 1位预测器（1-bit Predictor）

    ├── 相关预测器（Correlating Predictor）
    ├── Gshare 预测器
    └── 锦标赛/混合预测器（Tournament / Hybrid Predictor）
```

## 3. 静态预测

### 3.1 总不跳（Always Not Taken）

- 永远预测分支**不跳转**，顺序取下一条指令
- 准确率：约 **50%**
- 优点：硬件超简单
- 缺点：循环（loop）基本都跳，准确率很差

```
示例：
  for (i=0; i<100; i++) { ... }
  循环分支：99次跳，1次不跳
  "总不跳"预测准确率 = 1/100 = 1% ← 灾难性！
```

---

### 3.2 总跳（Always Taken）

- 永远预测分支**跳转**
- 准确率：约 **60-65%**（因为循环分支占多数）

---

### 3.3 BTFN（Backward Taken, Forward Not Taken）

- **向后跳**（loop 回到循环顶部）→ 预测**跳**
- **向前跳**（if 跳过一段代码）→ 预测**不跳**
- 准确率：约 **65-75%**
- 原理：向后分支基本是循环，跳的概率高

```asm
loop_top:
  ...
  BNE R1, R2, loop_top   ← 向后跳，BTFN 预测 "跳" ✓
  ...
  BEQ R3, R4, skip       ← 向前跳，BTFN 预测 "不跳"
  ...
skip:
```

## 4. 动态预测

### 4.1 1位预测器（1-bit Predictor）

**原理**：记录该分支上一次的结果，直接用作下次预测

```
状态：
  T = 上次跳了，预测下次也跳
  N = 上次没跳，预测下次不跳

状态转换：
  若预测正确 → 状态不变
  若预测错误 → 翻转状态（T↔N）
```

**例子**：循环分支（99次跳，1次不跳）

```
实际：T T T T T T ... T T N  T T T T...
预测：T T T T T T ... T T T  N T T T...
结果：✓ ✓ ✓ ✓ ✓ ✓ ... ✓ ✓ ✗  ✗ ✓ ✓ ...
```

每次退出循环：预测错 1 次（T→N）
下次进入循环：预测错 1 次（N→T）
**每个循环错 2 次**，相比循环次数：准确率较高，但每次进出循环都错。

---

### 4.2 ⭐ 2位饱和计数器（2-bit Saturating Counter）

**最常用的基础预测器！**

**4个状态**：

```
00 = 强不跳（Strongly Not Taken, SN）
01 = 弱不跳（Weakly Not Taken, WN）
10 = 弱跳  （Weakly Taken, WT）
11 = 强跳  （Strongly Taken, ST）
```

**状态转换图**：

```
        分支跳(T)          分支跳(T)
SN ←—————————————— WN ←—————————————— WT ←—————————————— ST
   ——————————————→    ——————————————→    ——————————————→
      分支不跳(N)          分支不跳(N)        分支不跳(N)
```

更清楚的图：

```
[SN] --T→ [WN] --T→ [WT] --T→ [ST]
      ←N--       ←N--       ←N--

预测：
  SN, WN → 预测 "不跳"
  WT, ST → 预测 "跳"
```

**关键优势**：比1位预测器更稳定——需要**连续2次错误才改变预测方向**

**例子**：循环（99次跳，1次不跳），初始状态 ST

```
实际：T  T  T ... T  T  N  T  T  T ...
状态：ST ST ST... ST ST ST WT ST ST ...
预测：T  T  T ... T  T  T  N  T  T ...
错误：✓  ✓  ✓ ... ✓  ✓  ✗  ✗  ✓  ✓ ...
```

每次退出循环错 1 次（ST→WT，还是预测T），
下次进循环再错 1 次（WT→ST）
→ 比1位预测器好（1位每次进出各错1次，总计相同，但稳定性更好）

**硬件实现（BHT - Branch History Table）**：

```
          分支PC的低N位
              ↓
BHT: [00|01|10|11|10|11|10|01|...]
      ↑                        ↑
   index 0                  index 255（若8位索引）

每个表项 = 一个2位饱和计数器
```

**BHT 大小计算**：
```
若 PC 低 10 位做索引：
  表项数 = 2^10 = 1024 个计数器
  每项 2 bit → 总大小 = 2KB
```

---

### 4.3 相关预测器（Correlating / Two-Level Predictor）

**动机**：2位计数器只看自己的历史，不看其他分支的模式

**例子**：

```c
if (a == 2) b = 1;        // 分支 B1
if (b == 0) c = 3;        // 分支 B2
// B2 的结果与 B1 高度相关！B1 跳了则 b=1，B2 一定不跳
```

**原理**：用**全局历史寄存器（GHR / BHR）** 记录最近 N 次分支结果

```
GHR（k位移位寄存器）：
  每次有分支：左移1位，最低位 = 本次是否跳（1=跳，0=不跳）
  
例：最近4次分支结果 = TNTN → GHR = 1010
```

**(2,2) 相关预测器**：用 2 位全局历史 + 2 位计数器

```
GHR（2位）：记录最近2次分支

4种历史组合：
  GHR=00（最近两次都不跳）→ 用自己的计数器 00
  GHR=01（不跳→跳）       → 用自己的计数器 01
  GHR=10（跳→不跳）       → 用自己的计数器 10
  GHR=11（两次都跳）       → 用自己的计数器 11

每个分支有 4 个计数器（每种历史各一个）
```

```
硬件结构：

         PC                GHR(2bit)
          ↓                    ↓
        [哈希 / XOR] ——————————→
                              ↓
                    PHT（Pattern History Table）
                    每项 = 2bit 饱和计数器
```

---

### 4.4 ⭐ Gshare 预测器

**最经典的相关预测器实现**

**原理**：

```
索引 = PC 低 N 位  XOR  GHR 低 N 位
                          ↓
                        PHT（2bit 计数器数组）
```

**示例（N=8）**：

```
PC 低8位:  1010 1100
GHR（8位）: 0011 1010
XOR 结果:  1001 0110  ← 用这个索引 PHT

PHT[0x96] 的计数器给出预测
分支实际结果更新 GHR 和 PHT[0x96] 的计数器
```

**优点**：
- 用 PC XOR 历史：不同 PC + 不同历史 → 通常映射到不同表项（减少冲突）
- 同样的硬件面积，比纯 BHT 更准

**硬件开销**：
```
N 位 GHR + 2^N 个 2bit 计数器
N=12 → 4096 个计数器 = 8KB
```

---

### 4.5 锦标赛预测器（Tournament / Hybrid Predictor）

**原理**：同时运行两个预测器，用 Selector 表决定信谁

```
                  分支 PC
                /    |    \
               ↓     ↓     ↓
          全局预测器  局部预测器  Selector表
               ↓           ↓         ↓
              预测A       预测B    {选A还是B}
                                      ↓
                                   最终预测
```

**Selector 表**：
- 也是 2bit 饱和计数器
- 记录历史上哪个预测器更准
- 每次预测后：若 A 对B错 → Selector 偏向 A；若 B 对A错 → 偏向 B

**Intel/AMD 现代处理器**：
- AMD Zen 系列用锦标赛预测器（Perceptron + TAGE）
- 准确率 > 99%

## 5. 各预测器对比总结

| 预测器 | 原理 | 典型准确率 | 硬件代价 |
|--------|------|-----------|---------|
| Always Not Taken | 无 | ~50% | 极低 |
| Always Taken | 无 | ~60% | 极低 |
| BTFN | 方向启发 | ~65-75% | 极低 |
| 1-bit BHT | 上次结果 | ~75-85% | 低 |
| 2-bit BHT | 饱和计数器 | ~82-90% | 低 |
| Correlating (2,2) | 全局历史+计数器 | ~88-93% | 中 |
| Gshare（12位） | PC XOR 历史 | ~93-97% | 中 |
| Tournament | 双预测器竞争 | ~97-99% | 高 |
| TAGE/Perceptron | 机器学习 | ~99%+ | 很高 |

## 6. 返回地址预测（RAS - Return Address Stack）

函数调用的返回地址用 **栈** 来预测，不用 BHT：

```
CALL foo   → 把 PC+4 压入 RAS
...
foo:
  ...
  RET      → 从 RAS 弹出地址，预测返回到 PC+4
```

RAS 通常 8-16 深度，深递归可能溢出。

---

## 7. BTB（Branch Target Buffer）

BTB 缓存**分支目标地址**，让 IF 阶段就能知道跳到哪里：

```
BTB 结构（类似 Cache）：
  Tag   | Target Address | Valid
  PC低位 | 跳转目标        | 1/0

命中时：取指直接跳到 Target Address
未命中时：先顺序取指，EX 阶段计算目标后才跳
```

**间接跳转**：`JMP R1`（目标在寄存器里）→ 需要 BTB，否则无法预测目标地址

## 8. Project 0 实验预期结论

你在模拟器里会看到：

1. **更大的 BHT** → 更低的缺失率（更少别名冲突）→ IPC 更高
2. **更多历史位** → 捕捉更复杂的分支模式 → 准确率更高
3. **Gshare > 纯 Bimodal** → 同面积下准确率更高
4. **流水线越深** → 错误预测代价越大 → 分支预测重要性越高
5. **不同 benchmark** → 分支行为不同 → 没有万能预测器

---

## 9. 关键公式

```
分支预测失误率 = 错误预测次数 / 总分支次数

IPC 影响：
  CPI = 1 + (分支频率 × 失误率 × 失误惩罚)

Speedup = CPI_差 / CPI_好
        = (1 + f×m_差×p) / (1 + f×m_好×p)

其中：
  f = 分支频率（如 0.20）
  m = 失误率（如 0.05）
  p = 失误惩罚（如 15 周期）
```
