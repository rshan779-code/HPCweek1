# 📘 CS6290 Project 0 — 专题 1：流水线基础（Pipelining）

> 流水线是理解分支预测"为什么重要"的前提。

---

## 1. 什么是流水线？

流水线把一条指令的执行拆成多个**阶段（Stage）**，让多条指令**重叠执行**。

### 类比：洗衣流水线

| 轮次 | 洗（30min） | 烘（30min） | 叠（30min） |
|------|------------|------------|------------|
| 衣物 A | 第1轮 | 第2轮 | 第3轮 |
| 衣物 B | 第2轮（A在烘时B开始洗） | 第3轮 | 第4轮 |
| 衣物 C | 第3轮 | 第4轮 | 第5轮 |

→ 每件衣物延迟不变，但**吞吐量大幅提升**！

---

## 2. 经典 5 级流水线

```
IF → ID → EX → MEM → WB
取指  译码  执行  访存   写回
```

| 阶段 | 全称 | 做什么 |
|------|------|--------|
| **IF** | Instruction Fetch | 从 PC 指向的地址取指令 |
| **ID** | Instruction Decode / Register Read | 解码指令，读寄存器 |
| **EX** | Execute | ALU 运算 / 计算地址 |
| **MEM** | Memory Access | 读写内存 |
| **WB** | Write Back | 把结果写回寄存器 |

**理想 CPI = 1**（每周期完成一条）

---

## 3. 流水线时序图（举例）

```
周期:    1    2    3    4    5    6    7
指令A:  [IF] [ID] [EX] [MEM][WB]
指令B:       [IF] [ID] [EX] [MEM][WB]
指令C:            [IF] [ID] [EX] [MEM][WB]
```

→ 第5周期起，**每周期完成一条指令**

---

## 4. 三种流水线冒险（Hazards）

### 4.1 结构冒险（Structural Hazard）

**原因**：多条指令争用同一个硬件资源

**例子**：只有一个内存端口，IF 和 MEM 同时需要访存

```
解决方法：
- 指令存储器和数据存储器分开（哈佛架构）
- 增加硬件资源
- Stall（气泡）
```

---

### 4.2 数据冒险（Data Hazard）

**原因**：后续指令依赖前面指令还没写完的结果

**例子（RAW）**：
```asm
ADD R1, R2, R3    # 第1条：R1 = R2 + R3
SUB R4, R1, R5    # 第2条：需要 R1，但第1条还没写回！
```

时序：
```
周期:    1    2    3    4    5
ADD:    [IF] [ID] [EX] [MEM][WB]  ← R1 在第5周期才写回
SUB:         [IF] [ID] [EX]...    ← 第3周期 ID 就需要 R1！
```

**解决方法 1 — 数据转发（Forwarding / Bypassing）**：
```
ADD 在 EX 结束后（第3周期末）就有结果，
直接把结果"转发"给 SUB 的 EX 阶段，不等 WB。
```

```
周期:    1    2    3    4    5
ADD:    [IF] [ID] [EX]→[MEM][WB]
SUB:         [IF] [ID]  [EX] ...
                         ↑ 从 ADD 的 EX 输出接收转发数据
```

**解决方法 2 — Stall（插入气泡）**：
```
周期:    1    2    3    4    5    6    7
ADD:    [IF] [ID] [EX] [MEM][WB]
SUB:         [IF] [ID] [NOP][NOP][EX] [MEM][WB]
                        ↑气泡  ↑气泡   ← 等 ADD 写回
```

**Load-Use 冒险（特殊情况，必须 stall 1 周期）**：
```asm
LW  R1, 0(R2)     # Load：MEM 阶段才能得到数据
ADD R3, R1, R4    # 立即使用 R1 → 即使转发也需要 stall 1 周期
```

---

### 4.3 控制冒险（Control Hazard）⭐ Project 0 重点

**原因**：遇到分支指令时，不知道下一条指令是谁

**例子**：
```asm
BEQ R1, R2, target    # 如果 R1==R2，跳到 target
ADD R5, R6, R7        # 不跳时执行这条
...
target: SUB R8, R9, R10  # 跳时执行这条
```

流水线在 BEQ 还没执行完时，已经取了 ADD 进流水线了！

```
周期:    1    2    3    4    5
BEQ:    [IF] [ID] [EX]...   ← 第3周期 EX 才知道跳不跳
ADD:         [IF] [ID]       ← 已经进来了（可能是错的！）
???:              [IF]        ← 这是谁？
```

如果 BEQ 确实要跳 → **必须冲刷（Flush）ADD 和后续错误指令** → 浪费 2 个周期

→ 这就是为什么**分支预测**非常重要！

## 5. 性能公式

```
执行时间 = 指令数(IC) × CPI × 时钟周期时间(T)

实际 CPI = 理想CPI(1) + 每条指令平均stall周期数
         = 1 + 分支预测失误惩罚×失误率 + 数据冒险stall
```

**例题**：
- 程序有 1,000,000 条指令
- 20% 是分支指令
- 分支预测准确率 90%（失误率 10%）
- 错误预测惩罚：3 个周期

```
分支stall = 20% × 10% × 3 = 0.06 cycles/instruction
实际 CPI = 1 + 0.06 = 1.06
```

若准确率提升到 99%（失误率 1%）：
```
分支stall = 20% × 1% × 3 = 0.006
实际 CPI = 1 + 0.006 = 1.006
Speedup = 1.06 / 1.006 ≈ 1.054（快了 5.4%）
```

## 6. 总结

| 知识点 | 关键词 |
|--------|--------|
| 流水线目的 | 提高吞吐量，CPI→1 |
| 结构冒险 | 资源冲突，加硬件解决 |
| 数据冒险 | RAW/WAW/WAR，转发+Stall |
| 控制冒险 | 分支不确定，需要分支预测 |
| Load-Use | 强制 stall 1 周期 |

> 💡 **Project 0 关联**：控制冒险（分支）直接影响 IPC，这是 Project 0 模拟器实验的核心观察对象。
