## 四、性能计算例题

### 例题 1：计算 IPC 和 CPI

**已知：**
- 总指令数 = 120,500,000
- 总周期数 = 85,432,100

```
IPC = 120,500,000 ÷ 85,432,100 = 1.4104
CPI = 85,432,100 ÷ 120,500,000 = 0.7092
```

---

### 例题 2：计算加速比（Speedup）

**场景：** 比较两种配置，以配置 A 为基准

| 配置 | 周期数 |
|------|--------|
| A（基准） | 85,432,100 |
| B（更好） | 72,300,000 |
| C（更差） | 100,000,000 |

```
Speedup(B vs A) = 85,432,100 ÷ 72,300,000 = 1.1816  （B 比 A 快 18.16%）
Speedup(C vs A) = 85,432,100 ÷ 100,000,000 = 0.8543  （C 比 A 慢）
```

> ⚠️ 加速比 = **基准周期数 ÷ 当前周期数**，必须保留 **4 位小数**

---

### 例题 3：CPI 分解（含分支失误惩罚）

**公式：**
```
CPI_实际 = CPI_理想 + 分支频率 × 失误率 × 失误惩罚
```

**已知：**
- 理想 CPI（无失误）= 0.5
- 分支指令占比 = 15%
- 分支失误率 = 5%
- 失误惩罚 = 10 周期

```
CPI_实际 = 0.5 + 0.15 × 0.05 × 10
         = 0.5 + 0.075
         = 0.575
```

**如果把失误率从 5% 降到 1%：**
```
CPI_新   = 0.5 + 0.15 × 0.01 × 10 = 0.515
Speedup  = 0.575 ÷ 0.515 = 1.1165
```

---

### 例题 4：估算分支失误惩罚

**方法：用 Oracle 和 Hybrid 的结果推算**

| 配置 | 周期数 | 分支失误次数 |
|------|--------|------------|
| Oracle | 70,000,000 | 50,000 |
| Hybrid | 85,000,000 | 240,000 |

```
额外周期数 = 85,000,000 - 70,000,000 = 15,000,000
额外失误次数 = 240,000 - 50,000 = 190,000

失误惩罚 ≈ 15,000,000 ÷ 190,000 ≈ 78.9 周期
```

## 五、分支预测器原理例题

### 例题 5：2-bit 饱和计数器

初始状态：`10`（弱跳转 Weakly Taken）

| 实际结果 | 操作 | 新状态 | 预测 |
|---------|------|--------|------|
| Taken   | +1  | `11` 强跳转 | 正确 ✓ |
| Taken   | +1  | `11` 强跳转（已最大）| 正确 ✓ |
| Not Taken| -1 | `10` 弱跳转 | 错误 ✗ |
| Not Taken| -1 | `01` 弱不跳 | 正确 ✓ |
| Not Taken| -1 | `00` 强不跳 | 正确 ✓ |

**关键优势**：需要连续 2 次预测错才会改变方向，比 1-bit 更稳定。

---

### 例题 6：Gshare 预测器工作流程

**配置：** 2 位 GHR，PHT 有 4 个条目（2-bit 计数器）

**GHR 初始：** `00`

**分支序列：** T, T, N, T（T=跳转，N=不跳）

| 步骤 | GHR | PC低2位 | 索引(XOR) | 预测 | 实际 | 结果 | PHT更新 | GHR新值 |
|------|-----|---------|-----------|------|------|------|---------|---------|
| 1 | 00 | 01 | 01 | NT(初始弱) | T | ✗ | PHT[01]→弱T | 01 |
| 2 | 01 | 01 | 00 | NT(初始弱) | T | ✗ | PHT[00]→弱T | 11 |
| 3 | 11 | 01 | 10 | NT(初始弱) | N | ✓ | PHT[10]→强NT | 10 |
| 4 | 10 | 01 | 11 | NT(初始弱) | T | ✗ | PHT[11]→弱T | 01 |

**准确率 = 1/4 = 25%**（冷启动阶段，PHT 没有学到足够信息）

---

### 例题 7：Tournament 预测器决策过程

```
输入 PC
    │
    ├──→ Bimodal 预测 → 结果 A
    │
    ├──→ GShare 预测 → 结果 B
    │
    └──→ Meta-predictor[PC] → 选 A 还是 B
              │
         2-bit 计数器
         11/10 → 用 Bimodal
         00/01 → 用 GShare
              │
              ▼
           最终预测

更新：如果 A 对 B 错 → Meta+1（倾向 Bimodal）
      如果 B 对 A 错 → Meta-1（倾向 GShare）
      两者都对/都错 → Meta 不变
```

## 六、AMAT 计算例题

### 例题 8：两级缓存系统

**配置：**
- L1：命中时间 1 周期，缺失率 8%
- L2：命中时间 10 周期，缺失率 40%
- 主存：访问时间 100 周期

```
AMAT = L1命中时间 + L1缺失率 × (L2命中时间 + L2缺失率 × 主存时间)
     = 1 + 0.08 × (10 + 0.40 × 100)
     = 1 + 0.08 × (10 + 40)
     = 1 + 0.08 × 50
     = 1 + 4
     = 5 周期
```

**如果去掉 L2（只有 L1 + 主存）：**
```
AMAT = 1 + 0.08 × 100 = 1 + 8 = 9 周期
```

→ L2 缓存让 AMAT 从 9 降到 5，提升 **1.8×**

## 七、ROB / Tomasulo 执行追踪例题

### 例题 9：ROB 状态追踪

```
指令序列：
I1: R1 = R2 + R3    （延迟 1 周期）
I2: R4 = R1 × R5    （延迟 3 周期，等待 I1）
I3: R6 = R7 + R8    （延迟 1 周期，无依赖）

周期 1：I1发射，I2等待R1，I3发射
周期 2：I1完成→R1=结果，I3完成
周期 3：I2获得R1，开始执行
周期 4：—
周期 5：I2完成
周期 6：按序commit I1, I2, I3（I3已完成，等I1/I2 commit后一起）
```

**关键：** ROB 保证**顺序 commit**，即使乱序执行，对外表现像顺序机器。

## 八、Amdahl 定律例题

### 例题 10：并行加速上限

**场景：** 程序 80% 可并行，20% 串行。使用 4 个核心

```
Speedup = 1 / (串行比例 + 并行比例/核心数)
        = 1 / (0.20 + 0.80/4)
        = 1 / (0.20 + 0.20)
        = 1 / 0.40
        = 2.5×
```

无论用多少核心，最大加速比：
```
Speedup_max = 1 / 0.20 = 5×（无穷多核心时）
```

## 十、常见坑

| 问题 | 正确做法 |
|------|---------|
| 加速比用 IPC 算 | 必须用 **nCycles**（周期数） |
| 小数截断不四舍五入 | 3.14159 → 3.1416，不是 3.1415 |
| 忘记备份配置文件 | `cp cmp4-noc.conf cmp4-noc.conf.bak` |
| 复制粘贴命令里的减号变成长横线 | 手动检查 `-` 符号 |
| 提交时压缩文件 | 每个文件单独上传 |
