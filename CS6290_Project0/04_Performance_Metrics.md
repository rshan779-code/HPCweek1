# 📘 CS6290 Project 0 — 专题 4：性能指标与计算

> Project 0 模拟器实验需要你分析和比较不同配置的性能数字，这里是所有公式和例题。

---

## 1. 核心性能公式

### 执行时间（最基础）

```
执行时间 = 指令数(IC) × CPI × 时钟周期时间(T)
         = IC × CPI / 频率(f)
```

### 性能（Performance）

```
性能 = 1 / 执行时间
```

### IPC 与 CPI

```
IPC（Instructions Per Cycle）= 每周期执行的指令数
CPI（Cycles Per Instruction）= 每条指令平均周期数

IPC = 1 / CPI
CPI = 1 / IPC
```

---

## 2. CPI 分解

```
实际 CPI = 理想 CPI + stall 周期数
         = 1 + CPI_data_hazard + CPI_control_hazard + CPI_struct_hazard

其中控制冒险（分支）贡献：
  CPI_control = 分支频率(f_b) × 失误率(m) × 失误惩罚(p)
```

### 例题 1：计算实际 CPI

**条件**：
- 理想 CPI = 1
- 分支指令占总指令的 20%（f_b = 0.20）
- 分支预测失误率 = 8%（m = 0.08）
- 失误惩罚 = 12 个周期（p = 12）
- Load-use stall：5% 的 load 指令后有立即使用，占指令总数 10%，即 0.5% 概率触发

**计算**：
```
CPI_control = 0.20 × 0.08 × 12 = 0.192
CPI_data    = 0.005 × 1 = 0.005  （每次 stall 1 周期）
实际 CPI    = 1 + 0.192 + 0.005 = 1.197
IPC         = 1 / 1.197 ≈ 0.835
```

## 3. Speedup（加速比）

### 基本公式

```
Speedup = 旧执行时间 / 新执行时间
        = (IC × CPI_旧 × T) / (IC × CPI_新 × T)
        = CPI_旧 / CPI_新
        = IPC_新 / IPC_旧
```

（假设指令数和频率不变）

### 例题 2：分支预测器改进带来的 Speedup

**条件**：
- 分支频率 20%，失误惩罚 10 周期
- 方案 A：失误率 10%
- 方案 B：失误率 2%

**计算**：
```
CPI_A = 1 + 0.20 × 0.10 × 10 = 1 + 0.20 = 1.20
CPI_B = 1 + 0.20 × 0.02 × 10 = 1 + 0.04 = 1.04

Speedup = CPI_A / CPI_B = 1.20 / 1.04 ≈ 1.154

→ 改进分支预测后，性能提升约 15.4%
```

## 4. Amdahl 定律

**场景**：只有部分程序可以被加速

```
Speedup_总 = 1 / [(1 - f) + f/S]

其中：
  f = 可以被加速的程序比例
  S = 该部分的加速倍数
  (1-f) = 不能被加速的串行部分
```

### 例题 3：Amdahl 定律

**条件**：
- 程序中 60% 的时间花在可并行的部分
- 用 4 个核心并行执行这 60% 的部分（S=4）

```
Speedup = 1 / [(1 - 0.6) + 0.6/4]
        = 1 / [0.4 + 0.15]
        = 1 / 0.55
        ≈ 1.82×

→ 即使 4 核并行，整体只快了 1.82 倍（瓶颈是那 40% 的串行部分）
```

**Amdahl 定律的启示**：
```
无论硬件多强（S→∞）：
Speedup_max = 1 / (1-f)

若串行部分 = 10%（f=0.9）：
Speedup_max = 1 / 0.1 = 10×（上限！再多核也没用）
```

## 5. AMAT（平均内存访问时间）

```
AMAT = 命中时间 + 缺失率 × 缺失惩罚
```

### 多级 Cache AMAT

```
AMAT = L1命中时间
     + L1缺失率 × (L2命中时间
                 + L2缺失率 × (L3命中时间
                             + L3缺失率 × 主存访问时间))
```

### 例题 4：计算 AMAT

**条件**：
- L1：命中时间 4 周期，缺失率 5%
- L2：命中时间 12 周期，缺失率 30%
- 主存：100 周期

```
AMAT = 4 + 0.05 × (12 + 0.30 × 100)
     = 4 + 0.05 × (12 + 30)
     = 4 + 0.05 × 42
     = 4 + 2.1
     = 6.1 周期
```

## 6. 分支预测相关计算 ⭐

### 6.1 预测精度与 IPC 的关系

| 失误率 | CPI（f=20%, p=15） | IPC |
|--------|-------------------|-----|
| 20%    | 1 + 0.20×0.20×15 = 1.60 | 0.625 |
| 10%    | 1 + 0.20×0.10×15 = 1.30 | 0.769 |
| 5%     | 1 + 0.20×0.05×15 = 1.15 | 0.870 |
| 1%     | 1 + 0.20×0.01×15 = 1.03 | 0.971 |
| 0.5%   | 1 + 0.20×0.005×15= 1.015 | 0.985 |

→ 失误率从 10% → 1%：IPC 从 0.769 → 0.971，**提升 26.3%**！

### 6.2 BHT 大小与准确率

BHT 表项越多 → 别名（aliasing）越少 → 准确率越高

```
若两个分支 PC 的低 k 位相同 → 共享同一个计数器 → 互相干扰
BHT 大小 = 2^k 项

k=4:  16 项，冲突严重
k=8:  256 项，冲突减少
k=12: 4096 项，冲突很少
k=16: 65536 项，几乎无冲突（但面积大）
```

### 6.3 历史长度与准确率

```
历史长度越长 → 捕捉更复杂的分支模式 → 准确率可能更高
但：
  历史太长 → PHT 太大 → 冷启动问题（每个表项训练次数少）
  
最优历史长度：通常 10-15 位（视 benchmark 而定）
```

```
新 CPI = 1 + 0.20×0.02×10 = 1.04
Speedup = 1.16 / 1.04 ≈ 1.115
```

## 8. 完整例题：比较两种预测器

**题目**：某程序在配置 A 和 B 下运行，数据如下：

| | 配置 A（Bimodal） | 配置 B（Gshare） |
|-|-----------------|----------------|
| 总指令数 | 5,000,000 | 5,000,000 |
| 分支指令数 | 1,000,000 | 1,000,000 |
| 预测失误次数 | 100,000 | 20,000 |
| 失误惩罚 | 15 周期 | 15 周期 |
| 时钟频率 | 3 GHz | 3 GHz |

**Step 1：计算失误率**
```
A: 100,000 / 1,000,000 = 10%
B: 20,000  / 1,000,000 = 2%
```

**Step 2：计算 CPI**
```
分支频率 = 1,000,000 / 5,000,000 = 20%

CPI_A = 1 + 0.20 × 0.10 × 15 = 1 + 0.30 = 1.30
CPI_B = 1 + 0.20 × 0.02 × 15 = 1 + 0.06 = 1.06
```

**Step 3：计算执行时间**
```
T_A = 5,000,000 × 1.30 / (3×10^9) = 2.167 ms
T_B = 5,000,000 × 1.06 / (3×10^9) = 1.767 ms
```

**Step 4：Speedup**
```
Speedup = T_A / T_B = 2.167 / 1.767 ≈ 1.226

→ Gshare 比 Bimodal 快约 22.6%
```
